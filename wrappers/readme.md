## Pacman Agent — Observation Space

This table describes the observation space defined in `CollectObservations(VectorSensor sensor)` in `Pacman.cs`. Positions are 0-based indices into the flattened ML-Agents observation vector, in the exact order the observations are added.


| Observation name | Observation position |
|---|---|
| Pacman position (Vector3: x, y, z) | 0–2 |
| Pacman attack state (bool) | 3 |
| Last action / input direction (int) | 4 |
| Movement direction (Vector2: x, y) | 5–6 |
| Ghost 1 position (Vector2) | 7–8 |
| Ghost 1 state (float) | 9 |
| Ghost 2 position (Vector2) | 10–11 |
| Ghost 2 state (float) | 12 |
| Ghost 3 position (Vector2) | 13–14 |
| Ghost 3 state (float) | 15 |
| Ghost 4 position (Vector2) | 16–17 |
| Ghost 4 state (float) | 18 |
| Power pellet 1 state (int) | 19 |
| Power pellet 2 state (int) | 20 |
| Power pellet 3 state (int) | 21 |
| Power pellet 4 state (int) | 22 |
| Normalised score (score / 3200) | 23 |
| Normalised lives (lives / 3) | 24 |
| Normalised remaining pellets (/ 244) | 25 |
| Normalised remaining power pellets (/ 4) | 26 |
| Fruit 1 state (float) | 27 |
| Fruit 2 state (float) | 28 |
| Closest pellet distance (Manhattan) | 29 |
| Ghost distances array (float[4], Manhattan) | 30–33 |
| Detailed game grid, flattened (int[width × height], constant length) | 34 to 33 + (width × height) |

**Total observations:** 34 fixed values (indices 0–33), followed by the flattened game grid of constant length `width × height`. The full vector length is therefore `34 + (width × height)`, fixed for a given maze layout.

## Game Grid
 
The grid is generated by `CreateDetailedGameGrid()` in Unity and flattened before being appended to the observation.
 
### Dimensions
 
- **Width:** 26 columns
- **Height:** 29 rows
- **Layout:** Row-major; cell at `(row, col)` lives at flat index `row * width + col`
- **Reshape:** `np.array(flat_grid).reshape(29, 26)` gives `(height, width)` orientation
- **Dimensions are constant** across all episodes because eaten pellets become value `0` in place — they don't get removed from the position list used to compute bounds.

### Cell Values

| Value | Entity                                         |
|---|------------------------------------------------|
| 0 | Empty cell, wall, or eaten pellet              |
| 1 | Active pellet                                  |
| 2 | Active power pellet                            |
| 3 | Pacman (normal)                                |
| 4 | Pacman (attack mode)                           |
| 5 | Ghost — home (5 + GhostState.HOME)             |
| 6 | Ghost — scatter (5 + GhostState.SCATTER)       |
| 7 | Ghost — chase (5 + GhostState.CHASE)           |
| 8 | Ghost — frightened (5 + GhostState.FRIGHTENED) |
| 9 | Ghost — eaten (5 + GhostState.EATEN)           |
| 10| Cherry                                         |

# Reward Structure
 
This table lists every **active** `pacman.AddReward(...)` call in `GameManager.cs`, i.e. the reward signal the ML-Agents agent actually receives. Score changes (`SetScore`) are *not* rewards and are excluded.
 
| Reward event | Reward value                                                | Where it is applied (method & condition) |
|---|-------------------------------------------------------------|---|
| Eat a pellet | +20.0                                                       | `PelletEaten()` — fires for every pellet eaten |
| Eat a power pellet | +50.0 (net **+70.0**)                                       | `PowerPelletEaten()` adds +50, then calls `PelletEaten()` which adds another +20 |
| Eat a ghost | +40.0                                                       | `GhostEaten()` — per ghost, fixed (the score `ghostMultiplier` does **not** scale this reward) |
| Clear the level (all pellets eaten) | +1000.0                                                     | `PelletEaten()` when `remainingPellets == 0` |
| Eaten by a ghost — lives remaining | -1000.0 (on single-life builds) -400 (on multi-life builds) | `PacmanEaten()`, `lives > 0` branch |
| Eaten by a ghost — final life / game over | -1000.0                                                     | `PacmanEaten()`, `else` branch (then ends episode) |
 
**Net active reward range per event:** -1000.0 (death) up to +1000.0 (level clear).

## Reward Wrappers

**There are a few wrappers that are always active** 
- Frameskip wrapper
  - Set to 4 frames
  - The number of frames between new observation the agents observations effecting the frequency at which the agent experiences the game
- Normalise Wrapper
  - we divide the total reward at every state by the max reward which is 1000 for clearing the level

## Behaviour reward wrappers
There will be a number of behaviours added to to each behaviour class.
For example: the `aggresstion` class will have `A1,A2,...,An`. I want to wrap the reward as such (below is just an example and should be treated as only an example):
```python
def wrap_env(env: Any, skip: int = 4, wrap_reward: str = None,step_reward:Optional[float]=None, caution: Optional[bool]=None,
             aggression: Optional[bool]=None,
             planning: Optional[bool]=None, cfg:Optional[Dict] = None) -> gym.Env:
             
    if skip is not None:
        env = FrameSkipWrapper(env, skip=skip)

    if step_reward is not None:
        env = StepRewardWrapper(env, step_value=step_reward)
    if caution is not None:
        env = CautionWrapper(env)
    if aggression is not None:
        env = AggressionWrapper(env)
    if planning is not None:
        env = PlanningWrapper(env)
    if wrap_reward == 'normalise':
        env = NormaliseRewardWrapper(env)

    return env
```
The cfg parameter will take in the reward values for the behaviours. Behaviour combinations are allowed e.g. You able to wrap the
env in both `A1` and `A3`, or just`A3`. Below is an example where the env should
only be wrapped with`A2`when `aggression = True`:
```python
cfg = {
    'A1': None,
    'A2': True,
    'A3': None,
    'C1': None,
    'C2': None,
    'P1a': None,
    'P1b': None,
}
```
Below is an example where the reward needs to be wrapped in both `P1a`and `P1b`:
```python
cfg = {
    'A1': None,
    'A2': None,
    'A3': None,
    'C1': None,
    'C2': None,
    'P1a': True,
    'P1b': True,
}
```
